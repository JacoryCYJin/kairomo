# 主题套件设计规范

确认日期：2026-10-29。

本文是 Kairomo 后续主题设计与开发的入口，定义主题可修改的区域及固定边界。开始主题任务前先读本文，再读 [展示系列与咖啡实现](display-series.md)。本文记录设计约定，不代表所有主题扩展能力已实现，也不授权直接修改现有界面。

## 1. 核心定义

一套主题是在多个产品区域中使用同一套视觉语言，分别提供适合该区域的设计。共享颜色、材质和意象，不要求共享构图或展示方式。

- 记录页提供筛选后的成果展示区域。咖啡罐是咖啡主题的具体设计，不是记录成果的通用标准。
- 小窗是专注与休息的使用场景，不必是记录页画面的缩小版。
- 容器、堆积、物理碰撞、液面、五档等级和“一条记录一个物件”都属于可选设计手法，不是套件通用要求。
- 主题解释真实记录，不创建另一套专注数据、积分余额或计时规则。切换主题不改变历史记录。
- 本文的“区域”指设计职责和边界，不要求把界面拆成可见的方框，也不要求增加 UI 选项。
- 小窗主题的可用画布是整个窗口；画布大小与图形实际占用范围分开定义。雪山可以只在下部，星空可以在上部，主题也可以使用边缘或全背景。不统一限制底部条带，也不强制铺满。

## 2. 套件区域总览

| 编号 | 设计区域           | 主要职责                   | 固定边界                           |
| ---- | ------------------ | -------------------------- | ---------------------------------- |
| A    | 小窗口显示区域     | 专注、休息时的主题表现     | 时间、文字、操作可读且稳定         |
| B    | 记录页主题展示区域 | 表现所选时间范围内的成果   | 遵守筛选结果，不改变日历和统计逻辑 |
| C    | 单条记录标识区域   | 在列表小尺寸位置体现主题   | 不挤压任务名称、时间及操作         |
| D    | 菜单栏状态区域     | 快速区分专注、休息、超时   | 保留状态含义与固定对齐规则         |
| E    | 主题专属设置区域   | 配置当前主题实际支持的选项 | 与通用外观、语言和短句设置分开     |

## 3. A · 小窗口显示区域

### 区域示意

```text
┌────────────────────────────────────┐
│ 关闭          版本标识     记录 设置 │
│                                    │
│               时间                 │
│                                    │
│             短句正文               │
│           作者／作品名             │
│                                    │
│             开始／暂停             │
│                                    │
└────────────────────────────────────┘
  整个窗口是可用画布；图形占用范围由主题决定，功能内容优先
```

### 可修改

- 主题背景、插画、材质、成果表现及克制的动效。
- 在底部、边缘或背景中组织构图，不限定为底部一条堆积区域。
- 数字、短句、署名和按钮的配色，但必须保持清晰对比和状态识别。
- 专注与休息采用不同画面，同属一套视觉语言。

### 保持统一

- 顶部功能入口、计时数字、短句与操作之间已确认的位置关系。
- 窗口宽度固定；无短句、仅正文、正文加署名使用三种固定高度。长句不换行撑高，超出时水平滚动；缺失作者或作品名时只显示已有字段。
- 主题图形不能遮住时间、文字、按钮，也不能迫使功能内容增加背景框来补救可读性。
- 不增加主题内部点击、手动翻页、领取奖励等操作，保持小窗沉静。
- 当天／本周决定成果取数范围，不规定物件数量或构图。不能新增本月选项。
- 累计成果与当前一轮的计时进度应可区分，不能用同一种变化制造歧义。
- 休息使用独立设计，不机械叠加专注成果。咖啡主题现有休息隐藏豆子的规则保留。

### 必须覆盖的组合

- 待开始、专注中、暂停、超时继续专注、休息待开始、休息中、休息暂停、休息结束。
- 无短句、仅正文、有作者／作品信息；短句关闭或内容为空。
- 当天／本周，无成果、少量成果、大量成果，浅色／深色。
- 隐藏后重开、首次打开与状态切换时，主题画面和功能内容同步就绪。

成果增加不能导致无限增高、缩小或变密。每套主题需定义饱和后的表现；完整数量和时长仍以真实统计为准。咖啡已确认的高度上限只约束咖啡主题，不是所有主题必须采用的几何规则。

## 4. B · 记录页主题展示区域

### 区域示意

```text
┌──────────────────────────────────────────┐
│                 页面导航                 │
├───────────────────┬──────────────────────┤
│                   │                      │
│    筛选与日历     │   B · 主题展示区域    │
│                   │   主题独立组织构图   │
│                   │                      │
│                   │   统计信息与日期     │
├───────────────────┴──────────────────────┤
│                 记录列表                 │
└──────────────────────────────────────────┘
```

### 可修改

区域内的构图、图形、场景、材质及成果与视觉之间的映射。可以表现为场景变化、生长、图案或其他形式，不要求容器、堆积或物件逐条累加。

### 保持统一

- 时间范围、日期选择、记录筛选、数量和有效时长的计算由产品负责。
- 主题读取筛选结果，不自行替换筛选含义或制造统计。
- 不改变日历、导航、记录列表结构及其操作。
- 统计文字、日期和画面之间保留清楚层级，不能只靠画面让用户猜数量或时长。

### 必须覆盖

空记录、单条、少量、大量及超出视觉承载量的情况；各种筛选范围；浅深外观；520／620 像素宽度。若采用动态或随机布局，说明重开、筛选切换、增加和删除记录时如何保持稳定。

## 5. C · 单条记录标识区域

```text
┌──────────────────────────────────────────┐
│ [C 标识]  任务名称               专注时长 │
│           起止时间                       │
└──────────────────────────────────────────┘
```

可设计小尺寸标识的形状、颜色和与记录的对应方式，不必沿用咖啡烘焙五档。此处仍是既定的小尺寸位置，不把完整场景塞入每一行。

保持任务名称、起止时间、时长、修正状态和编辑删除操作不变。不通过主题夸大或改变记录事实。必须检查小尺寸辨识度、浅深外观和不同记录状态，不能靠扩大行高来容纳复杂图案。

## 6. D · 菜单栏状态区域

```text
专注    [ 品牌 Logo   时间 ]
休息    [ 主题符号    时间 ]
超时    [    ＋      时间 ]
```

可设计休息符号、状态前景色与背景色。保留品牌 Logo、超时加号的含义，以及现有字体、数字锚点、图标间距、上下左右留白和无描边背景规则。

只因是否含小时切换两种占位宽度；不能随图标、当前数字、状态或背景边框变化跳动。图标须做视觉重量与数字中心对齐检查，不能仅比较外接框尺寸。

休息配色须与小窗在同一外观下对应。检查跟随系统、手动浅色、手动深色以及主题／外观切换；不能分别使用不一致的主题判断。新主题尚未接入前，不把现有菜单栏实现视为已支持任意主题。

## 7. E · 主题专属设置区域

```text
页面管理
  界面语言
  外观（跟随系统／浅色／深色）

主题设置
┌────────────────────────────────────┐
│ 主题                      当前主题 │
├────────────────────────────────────┤
│ 当前主题实际支持的专属设置         │
└────────────────────────────────────┘

自定义短句
  显示短句、展示方式、短句库
```

- 只列已实现的主题，不加入占位选项。
- 当前主题决定下方显示哪些专属设置；没有对应能力就不显示该项。
- 咖啡当前专属项为“小窗咖啡豆统计”，只支持当天／本周。这不是所有主题都必须拥有的设置。
- 通用语言、浅深外观、计时安排和自定义短句不归主题专属设置。
- 继续自动保存，不增加保存按钮和成功提示；不能覆盖无关偏好或进行中的计时。
- 新增主题专属参数时，另行定义持久化、默认值、校验和旧数据兼容，不假定当前数据结构已支持。

## 8. 共用视觉与验收要求

每套主题都需明确浅深配色、图形语言、材质、动效及状态映射，并检查：

- 时间和操作优先，装饰不竞争注意力，不靠高密度或持续运动制造成果感。
- 少量与大量内容都有完整构图；空状态不留下无意义占位。
- 动效低干扰，窗口隐藏时停止无必要的视觉计算；尊重减少动态效果的系统偏好。
- 作者、作品名、短句和四语言文案在实际窗口内可读，不溢出或挤压。
- 场景变化有真实数据依据；明确输入是什么、如何变化、何时达到视觉上限。
- 使用实际界面与状态截图验证，不能只以静态效果图、构建成功或图形尺寸相同宣称通过。

## 9. 新主题设计交付清单

设计新主题前，逐项填写；暂不采用的表现明确说明原因，不用咖啡形式补齐。

1. 主题名称、核心意象及整体视觉方向。
2. A：专注／休息小窗设计及三种文字布局。
3. B：记录页展示区域构图，以及不同筛选结果如何影响画面。
4. C：单条记录标识与映射规则。
5. D：菜单栏三种状态及浅深配色。
6. E：真正必要的主题设置、默认值与保存规则。
7. 空、少量、大量、饱和状态及各状态间的变化规则。
8. 浅深、语言、尺寸、可读性、对齐和性能的实际验证结果。

先展示设计和区域关系，经用户确认后再实施。此清单不表示每套主题必须使用收集、堆积、液体或持续动画。

## 10. 当前实现与接入步骤

基础设施版本：0.1.0-beta.4。当前提供咖啡与雪山攀登；不存在对用户开放的示例主题或外部插件加载器。

| 区域 | 已实现的通用入口                                                | 咖啡实现                                                           |
| ---- | --------------------------------------------------------------- | ------------------------------------------------------------------ |
| A    | `TimerVisualProps`，专注／休息组件和 `prepared` / `failed` 事件 | `coffee/CoffeeFocus.vue`、`CoffeeRest.vue`，物理与液体只在咖啡内部 |
| B    | `CollectionProps`，范围内记录、完成归属记录与真实总时长         | `coffee/CoffeeCollection.vue`                                      |
| C    | `RewardProps`，单条记录有效时长                                 | `coffee/CoffeeReward.vue`                                          |
| D    | 共用清单配色与打包图标，原生只绘制传入数据                      | `theme-kits/coffee/` 图标；共用清单内的咖啡配色                    |
| E    | `ThemeSettingsProps` 与按 schema 校验的局部保存                 | `coffee/CoffeeSettings.vue`；范围选项兼容旧 `bean_range`           |

新增主题时：

1. 先完成本文五个区域的设计并取得用户确认。
2. 在 `theme-kits/catalog.json` 登记 ID、四语言名称、浅深配色、菜单栏图标路径与选项 schema。没有选项时使用空 `options` 对象。图标置于 `theme-kits/<id>/`，构建会检查资源是否存在。
3. 在 `src/shared/series/<id>/` 实现独立组件，在 `renderers.ts` 注册全部六个入口；名称和原生数据不在多个页面重复维护。
4. `ThemeCanvas.vue` 统一提供全窗画布、圆角裁切、鼠标穿透、层级与首帧尺寸就绪处理。它通过 `ResizeObserver` 向主题传入只读 `canvas.width` / `canvas.height`，不规定图形高度。主题根节点填充画布，在内部决定图形布局，不重复创建窗口级裁切层。小窗组件只读 `state`、`records`、`dark`、`warmingUp` 和 `canvas`。完成首帧准备后发 `prepared(true)`，重新准备前发 `prepared(false)`；失败发 `failed`，不能让应用无限等待。专注组件在休息时可保持挂载但隐藏，以预热返回专注的画面；主题负责取消过期任务和销毁资源。
5. 专属设置组件发 `change`，载荷为该主题选项的局部键值。通用设置区绑定主题 ID，后端核对当前主题和 schema 后合并保存；枚举、布尔和有上下界的数值使用命名空间 `theme_options[主题ID]`。默认值由清单声明，读取走 `options.ts`，禁止自行直接写数据库或更改权威计时。
6. 旧咖啡范围继续读写 `bean_range`，由清单的兼容绑定处理，不复制进命名空间。其他主题不必提供范围设置；需要新参数就声明自己的 schema。
7. 执行 `npm test`、类型／格式／架构检查、Rust 测试与实际界面验收，核对非咖啡测试组件不会进入产品选择。

完整实现定位与兼容规则见 [展示系列](display-series.md)。菜单栏和首帧行为还需要真实 macOS 验收，不能以契约测试替代视觉检查。套件基础设施不代表新主题视觉已经设计完成，也不授权改变本文固定边界。

## 11. 雪山攀登首版

- 主题 ID 为 `snow-mountain`，六个组件位于 `src/shared/series/snow-mountain/`；图形从已选效果图经 ImageGen 整理为透明 PNG：`assets/mountain.png`、`focus-lower.png`、`rest-lower.png`、`climber.png`；SVG 仅作为等比例视口与人物定位容器，不再简化重绘山体。预览与交付共用这些资源。
- 记录页读取所选范围的真实有效专注总时长，每完整 30 分钟前进一段，共八段、四小时到顶。零记录在山脚；超过上限保持山顶，统计继续完整累计。删除、修正、切换筛选均由输入重新计算，不另存进度或积分。
- 小窗主题层覆盖整个窗口；本套雪山图形选择在下部展开，保留透明上部，不把该选择变成所有主题的高度限制。人物按本轮有效时长与目标时长的比值前进。暂停不增加进度；超时停在终点，计时规则不变；没有当前轮时回到起点。小窗不表达当天／本周累计成果，也不提供该范围选项。
- 小窗山体使用独立的 3:1 下部构图，按窗口宽度等比例显示（360px 宽时约 120px 高），左右山峰抬高、中央留出按钮空间；不拉伸原图，不让通用套件决定这项高度。休息营地沿用同一比例。记录区的主峰构图与路线保持独立。
- 休息独立显示避风营帐与暖色入口，不叠加登山者；没有循环动效、镜头或粒子，首帧同步准备，不启动 Worker 或动画计时器。
- 单条记录为冰镐，不分时长等级；菜单栏休息为营帐。浅深配色独立，品牌 Logo、超时加号、数字对齐规则不变。
- 首版 `options` 为空，选中后不添加专属设置行；现有主题和历史数据保持兼容。
- 开发预览增加 `series=snow-mountain`，`panel=timer` 支持 `kind=break`、`phase=idle|paused|running`、`elapsed=分钟`、`phrase=body|author`，均只使用内存测试数据。生产构建不包含预览。

### 真实渲染预览与差异口径

雪山预览使用实际组件和打包 DEV 窗口的截图，不以独立生成的整套 UI 图作为交付保证。对比固定设备、窗口尺寸、外观、日期、记录和计时状态；比较应用内容区的逐像素差异。主题区域替换与固定界面保持情况应分开报告。新截图尚未由用户确认时，不称为已批准基准；重复截图的稳定性不等于与原始概念图的还原误差。

### 咖啡适配全窗画布

咖啡专注根节点填充通用画布，内部保留 73px 的豆堆绘制区、原坐标和物理封顶；这个数值只归咖啡所有。咖啡休息根节点填充画布，液面继续依据实际全窗高度计算，首帧先同步读取高度再报告就绪。

开发预览 `panel=canvas` 仅用上下角标和中间命中按钮验证全窗能力，不注册为产品主题。`motion=still` 冻结预览动效以便同状态截图对照；不改变生产动效设置。
