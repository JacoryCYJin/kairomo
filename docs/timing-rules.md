# 计时与恢复规则

## 状态

状态为 idle、running、paused，会话种类为 focus 或 break。

- idle → 开始专注 → running/focus。
- running → 暂停 → paused；暂停不累加时长。
- paused → 继续 → running；建立新的有效区间。
- focus → 咖啡杯：保存已开始的专注记录，切到休息待开始；中间按钮显示“开始休息”，点击后才计时。
- break → 跳过休息：丢弃本轮休息历史，切到专注待开始并继承任务标题；中间按钮显示“开始专注”，点击后才计时。
- 待开始沿用 paused 检查点，pause_reason 为 ready、有效区间为空；等待不计时、不触发目标提醒。点击开始才创建首个有效区间、确定实际开始时间。退出重开仍待开始，不显示异常恢复提示。
- 专注和休息待开始时只显示中间的开始按钮，不显示或展开取消、结束及快进操作；核心拒绝未开始会话的取消、结束和切换请求，不改变状态或记录。判断依据是是否创建过有效计时区间，不能仅看时长是否大于零。开始后暂停仍可展开操作。待开始时修改目标应用于该阶段，已开始的阶段目标保持不变。
- 当前 focus → 结束本轮：保存有效专注时长，回到 idle；当前 break → 结束本轮：不保存休息历史，回到 idle。
- 取消本轮：确认后丢弃已开始的当前 focus 或 break，回到 idle，不生成历史或咖啡豆；保存失败保留原状态。确认携带会话编号，过期确认不能取消新一轮。
- 打开取消确认不会暂停或结束计时；Escape 或“保留本轮”只关闭确认。
- 非法或重复操作返回错误，不重复创建记录。

专注模式有“手动结束”（默认）与“到点结束”。手动模式达到目标只提醒一次，继续记录，点击咖啡杯才保存并切到休息待开始；到点模式在目标处结束并保存专注，然后切到休息待开始。休息不受专注模式控制，到点固定结束并切到专注待开始；不生成休息历史。所有阶段切换都不自动开始计时。

专注模式随当前轮开始时固定，修改模式仅影响下一轮专注；待开始阶段可以应用新的目标和模式。旧设置与旧会话缺少 focus_mode 时默认为 manual，不改变历史记录。该字段在现有 JSON 检查点与会话中保存，不改 SQLite 表结构。

自动结束按有效时长精确截到目标，调度晚到的部分不加入本轮，也不加入下一轮；开始、暂停、继续、切换请求绑定界面当时的会话与状态，自动到点先发生时不把旧按钮操作应用到下一阶段。完成记录与下一阶段待开始检查点原子保存，失败不发布新状态、不触发通知，重试不重复新增豆子。到点通知独立于结束模式，关闭通知不阻止阶段切换；通知使用到点阶段的信息，避免切换后误报成下一阶段的提醒。

手动模式下 50 + 12 分钟计为同一段 62 分钟。未满目标也保存；暂停和休息不进入专注总量。时长设置仅影响下一段会话。

## 时钟与存储

- 单调时钟用于有效时长，系统时间戳用于记录位置。不是每次界面刷新加一秒。
- 后台约每秒保存检查点并广播；隐藏窗口不影响核心。
- SQLite 完成专注记录与检查点同一事务提交，避免休息已开始但专注未保存。休息只保留当前倒计时暂停、恢复所需的检查点；结束、跳过或切换时不写入历史。运行时与存储层均排除休息及未完成会话。已有休息行不删除，但读取历史、统计和导出时均排除。
- macOS 睡眠事件通过 NSWorkspaceWillSleepNotification 原生通知送入 Rust runtime。睡眠暂停，唤醒不自动恢复；锁屏不等同休息。Windows 暂以调度间隔兜底处理，原生睡眠链路待 Windows 实测完善。
- 如果线程调度或系统事件丢失造成超过 8 秒的间隔，则保守地在最后确认位置暂停，将间隔视为未知，不自动计入。此策略也可能在机器严重卡顿时触发。
- 正常退出先暂停并保存；下次打开手动恢复。
- 异常退出后将正在运行的检查点恢复为暂停，并明确提示未知时间未计入。通常最多损失最后约一秒检查点间隔；存储异常时可能更长。用户可在结束后修正历史记录。
- Rust Instant 不保证各平台睡眠语义一致，因此不把“单调时钟”当作睡眠排除机制。[Rust 原文](https://doc.rust-lang.org/std/time/struct.Instant.html)

## 展示与修正

- 到点前显示剩余时间；手动专注到点后显示 +超出时间；到点结束的专注和休息显示下一阶段完整目标与开始按钮。
- 按本地日期将有效区间归到每日统计；跨午夜不全部算到开始日期。
- 修正记录允许标题与有效分钟数（0.01–1440），保留原始起止位置与暂停区间，按比例分配新的有效时长，并标记“已修正”。
- 列表及数量只包含已完成专注，进行中和休息不显示；图标按本轮有效专注时长显示烘焙档位。删除需界面确认；导出包含全部已完成专注，type 为 focus。CSV 对公式前缀进行处理。
- 本工具记录用户声明的专注，不推断真实认知投入，不因未操作键盘自动暂停。

## 咖啡豆与日历记录

- 每轮已结束的专注获得一颗咖啡豆，未达到目标的短专注也计算；进行中、休息和取消不获得豆。
- 咖啡豆按完成时间归属本地日期。跨午夜的同一轮只获得一颗豆，时长仍按有效区间分摊到实际日期。
- 咖啡豆系列按本轮有效时长分五档：不足 16 分钟浅烘，16–不足 32 分钟中浅烘，32–不足 44 分钟中烘，44–不足 60 分钟中深烘，60 分钟及以上深烘。同档固定豆色，浅色／深色模式分别配色；修正时长同步更新档位。
- 小窗仅显示本地当天完成的专注，最多六颗；每次新完成替换摘要里最短的一轮，午夜、唤醒或重新打开时重新核对日期。不限制历史获得的豆子总数。
- 记录页以历史会话直接计算豆子，不另存余额。日历选日、周、月、年、自定义及全部范围联动时长、咖啡罐和明细；罐下显示所选范围的真实专注时长，不通过豆数换算；收集区固定大小，完全不能滚动。
- 咖啡罐采用 cannon-es 的共同三维碰撞世界，所有豆子从罐口上方落入，实际装满后自然滚落；内部、外部共用同一桌面与碰撞规则，不预设左右或前景的散落位置。保留 SVG 图形和烘焙色，通过深度排序、朝向投影、玻璃遮挡表现层次；只显示稳定后的静态结果，不播放下落。罐子不随溢出缩小；整个画面最多展示该范围按完成顺序最先获得的 120 颗。达到展示上限不限制历史记录、完成轮数和真实总时长。
- 相同豆子编号复用最多八组的内存布局缓存；颜色和时长仍取当前记录。求解在 Worker 中运行，完成后释放，隐藏或离开页面取消未完成计算，再显示时按需重算。展示不参与核心计时和数据保存。
- 日历左右箭头只翻整月，不改变统计筛选；点击日期切换为当天。周从周一开始，月与年以选中日期所属时段为准。
- 自定义起止日期包含结束当天，内部使用本地次日零点作为排他的结束边界，不能用固定 24 小时替代日历日；无效范围不替换已生效的范围。
- 编辑、删除历史记录同步改变相应统计和咖啡豆；导出继续包含全部已完成专注。
