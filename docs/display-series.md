# 展示系列

系列只解释真实专注记录，不创建独立积分余额，也不影响计时。用户只能在设置里选择已实现的系列，不能修改系列参数。当前仅提供咖啡豆，不展示钞票等占位选项。

## 模块边界

- `src/shared/series/types.ts`：系列编号、名称和小窗摘要的公共约定。咖啡专属参数不强加给未来系列。
- `catalog.ts`：纯数据目录和未知编号兜底，不导入 Vue 或 Tauri。
- `renderers.ts`：系列的奖励与收集展示组件注册。
- `SeriesReward.vue` / `SeriesCollection.vue`：计时页、历史页使用的统一入口，通过当前系列编号选择组件。
- `coffee/definition.ts`：咖啡豆五档、双主题颜色、小窗六颗、目标容量和展示上限的唯一预设来源。
- `coffee/CoffeeReward.vue`：单颗豆子；`CoffeeCollection.vue`：开口罐和外部地面。
- `coffee/physics.ts`：只负责物理求解；`layouts.ts`：静态结果与有限缓存；`useCoffeeLayout.ts`：页面生命周期和取消过期计算。

未来新增系列应增加独立定义与两种展示组件，再注册到目录。不同系列可以有不同的评定与容器；不必复用咖啡烘焙等级或罐子。计时与统计页不直接判断咖啡种类。

设置持久化仍经过 shared/ipc → commands → runtime → storage。只新增 `visual_series` 偏好字段，旧检查点缺失字段时默认 `coffee`，不修改历史记录。偏好在 runtime 锁内合并，保存失败不覆盖当前选择，也不覆盖计时时长设置或进行中的会话。

## 咖啡豆预设

| 本轮有效专注时长  | 等级   |
| ----------------- | ------ |
| 不足 16 分钟      | 浅烘   |
| 16 至不足 32 分钟 | 中浅烘 |
| 32 至不足 44 分钟 | 中烘   |
| 44 至不足 60 分钟 | 中深烘 |
| 60 分钟及以上     | 深烘   |

阈值参考 Sweet Maria’s City 10:40 → City+ 11:05 → Full City 11:30 → Full City+ 11:50 → Vienna 12:15 的发展段比例，再映射到 0–60 分钟并取整。它是产品展示规则，不是整炉烘焙的统一分钟标准。[原始烘焙记录](https://library.sweetmarias.com/using-sight-to-determine-degree-of-roast/)

- 每轮已结束专注获得一颗；短任务也计算，进行中、休息和取消不计算。
- 小窗最多六颗，新完成替换其中最短一轮。
- 罐内目标容量约 80 颗，以共同三维碰撞世界的实际容积决定；所有豆子从罐口上方落入，不按编号预先指定哪些记录溢出。满后由求解结果确定罐外记录，再使用已确认的低矮堆积构图安排外部展示。
- 保留原有 SVG 图形和烘焙配色，将三维位置、朝向投影为简洁插画。按深度排序，区分玻璃内、罐后与罐前，配合轻微接触阴影和玻璃遮挡。每条完成记录只绘制一颗豆。
- 罐外构图由 `compactOverflow.ts` 与 `ExteriorBean.vue` 负责，保持原 SVG、记录身份与烘焙颜色；以豆子长轴控制朝向和厚度，明确排列遮挡顺序，不修改罐内姿态。
- 收集区整体最多展示最先完成的 120 颗，达到上限后几何保持饱和；完整历史、数量与时长继续累计。
- 罐子和取景比例不随数量变化；溢出可超出展示区，在窗口边界裁切，不引入横向滚动。Worker 后台求解，稳定后一次性显示，不播放下落；完成后释放 Worker 和物理世界。有限内存缓存只保存几何，不保存任务标题、颜色或时长。
- Bean SVG geometry 与 cannon-es 许可位于 `public/licenses/`。

## 开发预览与测试数据

先按项目规则检查已有服务，再使用 `npm run dev`。打开开发地址后添加 `?dev=series&gallery=1`，显示 20、40、80、110、120 颗的实际组件对照；`?dev=series&count=80` 显示单组。`theme=dark` 可预览深色。

预览页可切换 Collection / Gallery / History / Settings，设置改动只保存在预览页内存。测试记录使用 10、25、40、50、70 分钟覆盖五档，起止时间分散排列，不写入用户数据库，也不调用保存记录接口。

此入口只在 Vite 开发环境启用，生产构建移除预览入口与模拟数据。不得通过向用户正式 SQLite 注入记录来验收展示。

验证包含：分档前后 1 毫秒、六颗摘要、20/40/80/110/120 饱和、超过上限仍保留完整数据、稳定缓存、取消计算、不同任务编号的碰撞边界，以及旧检查点默认系列和保存失败不覆盖状态。
